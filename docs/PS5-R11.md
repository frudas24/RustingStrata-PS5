## Rationale and scope

The user's model inventory contains no F16/BF16 weight tensors. R8/R9 physical evidence identifies IQ2_XS gate/up, IQ3_XXS and IQ4_XS down. The non-cooperative routed IQ2_XS Vulkan path nevertheless rounds weights and activations to FP16 and accumulates FP32. The integer paths need the Q8-32 activation contract, not the legacy Q8K-256 CPU contract. Preserve the exact compressed file and model configuration. GPU improvements take priority; CPU contract candidates remain diagnostic until global parity is recovered.

| STRATA_PS5_R11_PROFILE=1 | prefill format/shape profiling, separately from performance | off |

The new IQ32 shader splits a routed tile (up to 128 tokens) into 32-token subtiles, retains the original tile-list ABI, half-rounding and per-output K order, and reduces static K/activation LDS from 27 to 13.5 KiB (not including ancillary allocations). It uses 8 rather than 32 accumulators per lane. Large routed tiles may lose weight reuse, so measure rather than promote. No packed INT8 acceleration is required. RPW experiments preserve the lane reduction and existing dispatch logic, and must show an actual changed dispatch. A candidate equal to the original RPW is not evidence of speedup.

IQ2 CPU vectorizes across eight independent output rows, preserving sequential FMA order within a row, using bounded 8 KiB dequantized block scratch per job. Q32 prepares one activation once per projection, unpacks IQ3/IQ4 codes and scales from compressed blocks and uses signed 16-bit widening plus exact 32-bit dot reductions. The unpack itself is scalar. No full expert expansion. The Q32 scaling order targets the noncoop shader but is not established as bit-identical to Vulkan. The CPU benchmark has a same-contract scalar reference and the existing (different-contract) Q8K baseline; do not conflate either with GPU or whole-model timings. Reusing input preparation across gate/up and weights across tokens is future work; SiLU is unchanged and there is no new gate/up/down fusion.

## GPU performance and quality, independent of R4

```bash
python3 tools/ps5/bench-r11.py --model "$MODEL_MOE" --candidate iq32 --out results/r11-iq32-8k --ctx 8192 --pp 128,512,2048,4096 --tg 32 --reps 3
# Same command, with unique output directory, for gemv1/2/4/8 and down1/2/4/8.
python3 tools/ps5/bench-r11.py --model "$MODEL_MOE" --candidate iq32 --out results/r11-iq32-profile --profile-only
python3 tools/ps5/quality-r11.py --model "$MODEL_MOE" --candidate iq32 --corpus "$QUALITY_CORPUS" --out results/r11-iq32-quality --ctx-len 512 --chunks 4
```

Use a representative held-out corpus (Spanish/English text and code, at least 2048 tokens for the default quality run). Quality script requires complete, identical encoded full-vocabulary logprob dumps. Encoding is lossy: this does not establish raw-logit identity. If different, inspect KLD, token probabilities and generation, but keep the strict gate failed. Compare against the unchanged same-quantization baseline; this does not establish equivalence to full-precision Qwen. GPU ABBA requires actual dispatch, stable repetitions, matching greedy fingerprints and top-5 prefill signatures, >=3% geometric throughput gain and no phase/workload >5% regression. Keep candidate flags off until both gates pass and final combined config is revalidated. Record separate TTFT, prefill, decode, p95 latency, memory and cache hit rates when available. Profile only in separate runs; no acceptance from timestamps alone. Sweep context 32K and 64K for finalists, with PP up to 32256 and 65024 respectively and reserve generation space. Compare against the historical R7 control separately. MTP remains a separate future campaign.
