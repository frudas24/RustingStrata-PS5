## Motivation and scope

The previous physical R13 report identified the general integer GEMM as about 41.6% of the recorded active GPU intervals in the instrumented prose workload, and Q5_K/Q6_K as the dominant dispatch types in that kernel. These are historical observations, not measurements of R14. R12 IQINT64 passed 8K quality and performance; context-long acceptance was incomplete (natural EOS in the baseline and variable decode). R13 LDS passed parity but did not meet ROI. Retain all previous code and flags.

R14 implements two research mechanisms and diagnostics, not all potential future work. Causal mixer internals, new attention/DeltaNet arithmetic, TMU/VCN/SDMA and alternate weight-loading policy are deferred. Profile first; do not add those mechanisms before evidence. Existing R2/R7 dense shaders already implement the 32/64-position tiling. Reuse them instead of duplicating GLSL; R14's novelty is selective dispatch for Q5_K/Q6_K and direct validation on their real shapes. The 32-position variant is not gated on *accelerated* dot: the baseline non-cooperative shader already requires the integer-dot feature and the software-dot variants use the same instruction path. Exact compiled resource sizes and numerical identity must still pass on the physical device.

## Flags

- `STRATA_PS5_R14_DENSE_TILE=0|32|64` (default 0).
- `STRATA_PS5_R14_DENSE_TYPE=q5|q6|both` (default both, inert when tile=0).
- Requires PS5 profile, wave32 and `ps5-r2` build when active. Cooperative integer, routed and FP16 paths keep their original selection. Conflicting R2/R7 dense flags are rejected. Dispatch uses z=1 (no split-K), same quantized activation, scales, min correction and full K. Only dense Q5_K/Q6_K affected; Q8_0 not changed.
- `--fixed-decode`: benchmark-only, requires generic Vulkan runner, R6 fingerprints, MTP=0, sufficient explicit context. Feed exactly `tg` continuation tokens from the same tokenized sequence as the prompt; do not stop on predicted EOS. Measure GPU greedy step/argmax, **not** free text generation. JSON records input IDs, forced IDs and predicted IDs; checker hashes the complete prompt and requires identical predictions between arms. Other bench callers reject fixed-mode results by default.
- `--fixed-logits PATH`: additionally capture full FP32 logits after prefill and every forced step (separate readback path, not scored). File created exclusively, little endian, rows in workload/repetition/step order. JSON includes vocabulary and row count. Validate exact byte length, finiteness, consistency with predicted maxima, SHA-256 equality. The candidate must also pass natural generation and encoded KLD checks; raw identity is scoped to captured positions.
- Natural mode permits consistent early EOS, does not score performance. Existing R6/R11/R13 gates keep strict length and reject a fixed-mode record. Do not compare the new fixed-work decode rates with previous free-generation rates as if they were the same experiment.
- Profile mode records kernel labels by dense type, existing allocation/Q8/copy records, and the `r7_load` wall-clock boundary. Copy sums before and after the marker are diagnostic, not exclusive wall time. GPU active intervals exclude unrecorded graph replay work, so not total runtime. Do not score profiling or full-logit mode.
